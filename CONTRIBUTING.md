# Как вносить изменения

1. Задача — issue. Под неё ветка, работа — через Pull Request в `main`;
   напрямую в `main` не пушим.
2. Коммиты — [Conventional Commits](https://www.conventionalcommits.org/) на
   русском: `feat: …`, `fix: …`, `docs: …`, `chore: …`.
3. PR на русском: сначала что и зачем, потом как. Какие статьи документации
   Битрикса и файлы ядра прочитаны — тоже в PR.
4. Перед PR — `./build.sh --check` зелёный: имена файлов, списки поставки,
   кодировка, `php -l`, строчные имена в `lib/`, версия, тесты.
5. Код с логикой — с тестом в том же PR (`tests/<имя>_test.php`, обвязка
   `tests/assert.php`). Тест должен краснеть, если сломать код.
6. Документация (`docs/`, `README.md`, `CHANGELOG.md`) — в том же PR.
7. Меняется `lib/`, установщик или языковые файлы — версия в
   `install/version.php` и запись в `CHANGELOG.md`.
8. Ядро Битрикса и модуль `note` не правим — только своё.
9. Мерж — squash, после зелёного CI и ревью (навык `review-panel`).
