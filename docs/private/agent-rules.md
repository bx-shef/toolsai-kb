# Правила процесса

> Последняя сверка: 2026-10-16

Правила линейки одни на все модули. Канон —
[docs/private/agent-rules.md shef.toolsai](https://github.com/bx-shef/toolsai/blob/main/docs/private/agent-rules.md);
здесь — коротко и то, что отличается.

1. **Источники.** Документация Битрикса (`.bitrix-docs/framework-docs`), код
   ядра портала (`bitrix/modules/note`), навыки линейки. Не выдумывать
   классы и методы. Расходится документация с ядром — прав код ядра;
   отметить в PR. Опорные точки `note` — [00-research.md](00-research.md).
2. **Путь до `main`** — только PR. Ветка, коммиты Conventional Commits на
   русском, PR на русском: что и зачем, потом как.
3. **Ревью.** `/code-review` на каждый PR; панель из пяти (документация,
   инженер, QA, безопасность, CTO) — на изменения поведения, публичного API
   (`Shef\ToolsAiKb\Public\…`, событие), схемы таблицы, кодов настроек,
   установщика, CI. Порядок — навык `review-panel`.
4. **Мерж** — squash, после зелёного CI и пройденной панели, с явного
   разрешения владельца. Навык `merge-pr`.
5. **Дисциплина.** Тест должен краснеть, если сломать код. Документация — в
   том же PR. Никогда `git checkout --` для отката чужого.
6. **Решает владелец**: удаление данных в `note`, изменение формата события,
   смена кода раздела/пакетов, необратимые миграции.
