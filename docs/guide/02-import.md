# Импорт статей

## Когда идёт

- при установке модуля (первый импорт);
- агентом `\Shef\ToolsAiKb\Agent\Refresh::run();` раз в сутки — если включена
  настройка «Обновлять статьи раз в сутки» (`KB_agent`, по умолчанию да);
- кнопкой «Обновить статьи» на странице настроек
  (`/bitrix/admin/settings.php?mid=shef.toolsaikb`, нужно право записи на модуль).

Два импорта одновременно не идут: блокировка `shef.toolsaikb.import`
(`Shef\Options\Main\TempFile\Pid`). Занято — кнопка скажет «импорт уже идёт».

## Что происходит

1. Событие `OnKbSourcesCollect` собирает пакеты ([формат](03-events.md)).
2. Раздел: ID — в служебной настройке `SYS_collectionid`.
   - есть — пополняется;
   - удалён — создаётся новый (`KB_collectionname`, по умолчанию «ИИ: База знаний»);
   - **в архиве — импорт не идёт** и пишет ошибку: архив — решение человека.
     Верните раздел из архива или удалите его.
3. На каждый пакет — документ верхнего уровня с названием пакета, под ним —
   статьи. Порядок статей — по пути файла (`10-…` раньше `20-…`).
4. Каждая статья решается так (`Import\Planner`):

| ситуация | что делает импорт |
|---|---|
| статьи ещё нет в таблице соответствий | создаёт документ |
| документ удалён из `note` совсем | создаёт заново |
| документ в архиве | не трогает |
| документ в корзине | не трогает (выясняется при перезаписи) |
| в `note` лежит не то, что импорт записал последним, или документ открывали в редакторе (формат не `md`) | **не трогает — правка человека** |
| статья в пакете не менялась | ничего |
| статья изменилась, документ не трогали | перезаписывает заголовок и текст |

5. Статья, которой больше нет в пакете, и все статьи пакета, которого больше
   нет в событии, **уходят в корзину** «Базы знаний» (`Import\Planner::decideObsolete()`,
   команда ядра `DeleteDocumentCommand`). Из корзины их можно восстановить.
   Запись в таблице соответствий убирается.

| ситуация | что делает импорт |
|---|---|
| документ не трогали | убирает в корзину |
| документ правили руками (как выше) | **не трогает**, пишет в отчёт |
| документ в архиве | не трогает, пишет в отчёт |
| документа уже нет или он в корзине | только убирает соответствие |

   Страница пакета уходит в корзину последней и только если под ней не
   осталось оставленных статей: ядро уносит документ вместе с вложенными.
   Если под статьёй или страницей пакета есть документ, которого импорт не
   создавал (его вложил человек), она **не удаляется** — в отчёте «оставлен —
   под ним документы, созданные вручную». Дерево раздела импорт берёт у ядра
   (`TreeProvider::getTree()`); архивные и документы в корзине ядро в нём не
   показывает.

   **Защита от сбоя:**
   - событие не вернуло ни одного пакета — не удаляется ничего;
   - сбор пакетов прошёл с ошибками (упал обработчик, отклонён ответ) —
     пропавшие пакеты не удаляются;
   - пакет прочитан с ошибками или пришёл без единой статьи — его статьи не удаляются.

## Файл статьи

- `*.md` в каталоге пакета и подкаталогах; скрытые (`.…`) пропускаются;
  ссылки за пределы каталога не читаются; каталоги-ссылки не обходятся;
- заголовок — первая строка `# Заголовок` (из текста убирается); нет её —
  имя файла без номера: `10-first_steps.md` -> «First steps»;
- путь от каталога пакета — не длиннее 255 символов; текст — не больше
  1 МБ (ограничение `note`).

## Итог

Строка вида «пакетов: 1, создано: 3, обновлено: 0, без изменений: 12,
правлены руками (не тронуты): 1, в архиве (не тронуты): 0,
удалено в корзину: 2, нет в пакете, оставлены: 1, ошибок: 0» —
на странице настроек (последний импорт) и после кнопки. Ошибки — в журнал
shef.problems (Настройки → Учёт проблем) и в журнал событий.

## Автор документов

Служебный пользователь shef.options (`DEF_systemuserid`, по умолчанию ID 1).
Он же модератор раздела.
